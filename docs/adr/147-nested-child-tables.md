# ADR-147: Tables inside the rows of a table

**Status:** accepted (platform)

## Context
A child table's rows could not hold a table of their own ("a child table cannot contain another table", ADR-004). Real documents have that shape: an order with lines and each line with serial numbers, an assembly with lines and each line with parts, a survey with questions and each question with choices.

## Decision
- **One level deep.** A child DocType may have `Table` fields whose target is another child DocType, provided the target holds no table itself and is not already the rows of a table inside another child. The rule needs the other DocTypes, so `MetaRegistry.CheckReferences` enforces it (with a message that says tables nest one level deep, and the reverse check when a DocType that is already used inside another child starts holding a table). The single-definition check no longer refuses a table in a child. Two levels cover the real shapes; a third multiplies every cost below for little gain.
- **Storage is the existing child table storage.** The inner rows live in their own table and name the row that holds them as `parent`, that row's DocType as `parenttype` and the field as `parentfield`. Nothing in the schema changes. Reading is `GetChildrenAsync(inner, holderDocType, holderRowName, field)`.
- **Everything cascades in SQL, in the same transaction.** Deleting a document deletes the inner rows first, found through the rows that hold them (`DELETE ... WHERE parent IN (SELECT name FROM holder WHERE parent = @doc ...)`); removing a row from a table deletes its inner rows; a merge deletes them with the old document. A rename needs nothing (inner rows point at row names, which do not change). The in-memory repository does the same, and PostgreSQL tests cover save, edit, removal, delete, rename and merge.
- **One save, one walk.** Rows carry their inner tables (`RowInput.Tables`), and every place that visited rows now visits them depth-first (`TableInput.AllRows`): defaults, "fetch from", expression defaults, formulas, field validation, the DocType's rules, required tables and the row limit. Errors keep the whole path (`lines[0].parts[1].qty`). A row's formulas can read the rows inside it (`sum(parts, 'qty')`), an inner row's `parent` is its row, and totals settle in the same three passes. A saved row sent without its inner table keeps it (and the formulas still see it), and an inner row can only name a row its own row holds.
- **Limits.** One save may carry at most 10,000 rows across all its tables and inner tables (each table still holds at most 1,000).
- **What rides along.** The updates log records an inner change as `lines › parts` (visible to people who may see `lines`); the kept copy of a deleted document holds the inner rows and a restore puts them back under the same row names; amend, auto repeat and the Desk's duplicate copy them without ids; the default print shows them under their row; `GET /api/meta` sends every child DocType, so the Desk can draw the inner grid.
- **The Desk** shows an inner table in the row's details panel (the pencil), with the same grid, CSV and reorder controls, its errors scoped to the row, and live formulas that see the inner rows. The Designer allows a Table field in a child DocType and offers only child DocTypes that hold no table themselves.

## Consequences
- A form with many rows that each hold a table loads one query per row for the inner rows (and the same on a save that has to compare them): acceptable at the sizes forms have (1,000 rows per table at most), but not for bulk loads.
- Filtering a list by inner rows arrived with [ADR-151](151-nested-row-filters.md). Not yet: reports, imports and exports on the inner rows; conditions ("show when") and rules of inner rows are enforced on save but not live on the form; Customize Form on child tables; three levels.
- Found by running it in a browser: the form's own live formulas must know the new row shape too, or they overwrite the saved totals and mark the form unsaved; the Desk logic engine now walks the inner rows the same way the server does.
